# Project page guide

A project page is a living technical story, not a copy of a paper and not a chronological dump of every file. It should help a visitor understand the problem, Dong Qiang's contribution, the technical idea, the evidence, and how the project evolved.

## Possible anatomy

1. **Project hero** — title, one-line description, verified status/year/tags, and one strong image or video.
2. **Overview** — the problem, context, role, and central contribution.
3. **Demo / media** — selected demonstrations that clarify the work.
4. **System / design / method** — hardware, software, mechanism, experiment, or process as appropriate.
5. **Results** — only verified results, with enough context to interpret them.
6. **Updates** — dated milestones that preserve project history.
7. **Publications / code / links** — related records and external resources.
8. **Related projects** — meaningful connections, not generic recommendations.

Every section is optional. VEX work may have no publication section. A prototype may have no formal results section. A publication-backed research project may need detailed methods and results. An ongoing robotics project may emphasise demonstrations and updates.

Keep one stable page as a project evolves. Add new milestones and capabilities to that page unless the work has genuinely become a distinct project with its own purpose and source material.
